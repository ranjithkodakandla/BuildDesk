# Cloud SQL Configuration & Deployment Guide

This document outlines the steps to set up, configure, and secure a managed PostgreSQL instance on Google Cloud SQL, and integrate it with a Cloud Run service using Google Secret Manager for secure credentials.

## 1. Cloud SQL PostgreSQL Instance Creation

Provisioning a Cloud SQL instance should be done carefully to control costs for development/demo environments.

### Recommended MVP Configuration:
- **Region:** `us-central1` (match with Cloud Run service)
- **Database Version:** PostgreSQL 15
- **Tier:** `db-f1-micro` (Shared Core) - The most cost-effective tier for lightweight use cases.
- **Storage:** Minimal (e.g., 10GB SSD)
- **Backups:** Automatic backups enabled (if inexpensive).

### Provisioning via gcloud:
```bash
gcloud sql instances create builddesk-db \
    --database-version=POSTGRES_15 \
    --region=us-central1 \
    --tier=db-f1-micro \
    --project=stonedesk-app
```

## 2. Database and User Creation

Create the database and a dedicated application user within the instance.

```bash
# Create database
gcloud sql databases create builddesk --instance=builddesk-db --project=stonedesk-app

# Create dedicated application user
gcloud sql users create builddesk_user --instance=builddesk-db --password='YOUR_SECURE_PASSWORD' --project=stonedesk-app
```

> [!WARNING]
> Ensure your secure password does not contain unsafe characters that could break connection URLs, or properly escape them when saving as a connection string.

## 3. Secret Manager Integration

Cloud Run services should not store secrets in plaintext. Use GCP Secret Manager.

### Format the Connection String
The connection string to be used within Cloud Run uses the Unix Domain Socket generated by the Cloud SQL Auth proxy (injected by Cloud Run).

```text
postgresql+psycopg://USER:PASSWORD@/dbname?host=/cloudsql/PROJECT:REGION:INSTANCE
```

**Example:**
`postgresql+psycopg://builddesk_user:YOUR_SECURE_PASSWORD@/builddesk?host=/cloudsql/stonedesk-app:us-central1:builddesk-db`

### Store in Secret Manager
```bash
echo -n "postgresql+psycopg://USER:PASSWORD@/dbname?host=/cloudsql/PROJECT:REGION:INSTANCE" | gcloud secrets create BUILDDESK_DATABASE_URL --data-file=- --project=stonedesk-app
```

## 4. Networking and Connections

### Connecting from Local Development
To connect to the database from your local machine, use the [Cloud SQL Auth Proxy](https://cloud.google.com/sql/docs/postgres/sql-proxy).

```bash
./cloud-sql-proxy stonedesk-app:us-central1:builddesk-db &
```

Set your local `.env` file to connect via the proxy:
```dotenv
DATABASE_URL="postgresql+psycopg://builddesk_user:YOUR_SECURE_PASSWORD@localhost:5432/builddesk"
```

### Running Migrations
Use the proxy connection to run Alembic migrations safely from your local machine to the remote Cloud SQL instance:
```bash
DATABASE_URL="postgresql+psycopg://USER:PASSWORD@localhost:5432/builddesk" alembic upgrade head
```

## 5. Security & IAM Roles

Cloud Run runs using the default Compute Engine service account. It requires explicit permissions to access the Secret Manager and Cloud SQL.

```bash
PROJECT_NUMBER=$(gcloud projects describe stonedesk-app --format="value(projectNumber)")

# Allow Cloud Run to access the database URL secret
gcloud projects add-iam-policy-binding stonedesk-app \
  --member="serviceAccount:$PROJECT_NUMBER-compute@developer.gserviceaccount.com" \
  --role="roles/secretmanager.secretAccessor"

# Allow Cloud Run to use the Cloud SQL Auth proxy
gcloud projects add-iam-policy-binding stonedesk-app \
  --member="serviceAccount:$PROJECT_NUMBER-compute@developer.gserviceaccount.com" \
  --role="roles/cloudsql.client"
```

## 6. Live Deployment

With the secret configured and the permissions granted, deploying via the `Makefile` automatically binds the Cloud SQL instance and injects the database connection string.

```bash
CLOUDSQL_INSTANCE=stonedesk-app:us-central1:builddesk-db GCP_PROJECT_ID=stonedesk-app make deploy-cloudsql
```
